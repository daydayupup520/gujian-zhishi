## 第一章　项目概述

### 1.1 背景分析

中国拥有超过76万处不可移动文物，其中古建筑占比超过40%。据第三次全国文物普查数据显示，约4.4万处不可移动文物已消失，大量古建筑正面临自然侵蚀、人为破坏和保护资源不足的严峻挑战。

传统古建筑保护工作高度依赖专家现场勘察，存在以下突出问题：

1. **识别效率低下**：建筑类型、年代、构件特征的判定需要数十年经验积累，基层文保单位严重缺乏专业人才，一次完整勘察往往需要3-7个工作日；
2. **病害诊断主观性强**：不同专家对同一病害的严重程度判定差异可达30%以上，缺乏量化标准；
3. **保护决策缺乏数据支撑**：修缮方案多凭经验制定，难以进行长期效果预测和成本效益分析；
4. **信息孤岛严重**：建筑档案、病害记录、修缮历史分散在不同部门，无法形成系统性认知。

"古建智识"系统应运而生，旨在将多模态AI视觉识别、3D可视化、病害预测模型、历史地理信息系统等前沿技术深度融合，构建一套从"智能识别→病害诊断→对比分析→保护决策"的全链路数字化古建筑保护平台，大幅降低文物保护的技术门槛，让每一个人都能成为古建筑的守护者。

### 1.2 政策指导

本系统的设计与实现紧密响应国家文化遗产保护的战略部署：

- **《关于加强文物保护利用改革的若干意见》**（2018年，中共中央办公厅、国务院办公厅）：明确提出"推进文物保护利用与现代科技融合发展"，鼓励运用人工智能、大数据等技术赋能文物保护。
- **《"十四五"文物保护和科技创新规划》**（2021年，国务院办公厅）：将"文物数字化"列为重点任务，强调建设文物资源大数据体系，推动文物保护从经验驱动向数据驱动转型。
- **《关于让文物活起来、扩大中华文化国际影响力的实施意见》**（2022年）：倡导运用数字技术让文物"活起来"，增强公众参与度和文化认同感。

本系统通过AI智能识别降低专业门槛，通过3D可视化实现沉浸式展示，通过数据驱动的决策支持提升保护效率，全面契合"科技赋能文物保护"的政策导向。

### 1.3 系统特色

本项目主要特色如下：

**1）多模态AI视觉融合识别**

集成智谱GLM-4V-Plus多模态大模型，支持多角度图片联合输入，通过跨视角一致性校验（Fusion Consistency Score）实现建筑类型、年代、构件特征的高置信度识别。单次识别可输出建筑名称、类别、年代、地理位置、斗拱类型、走兽数量、彩画纹样、屋顶形式等12项结构化指标，覆盖皇宫、官府、民居、桥梁四大类别。

**2）病害3D热力图可视化与50年预测**

基于Three.js/React Three Fiber构建的交互式3D模型，针对四种建筑类型设计了差异化的几何模型（皇宫殿宇、官府衙署、民居院落、古桥），将病害数据映射为空间热力球。系统内置病害恶化预测模型，可推演5年、10年、20年、50年后的结构安全评分和维修紧急度。

**3）全链路保护决策闭环**

从识别到保护形成完整闭环：AI识别建筑→诊断病害→对比分析→风险模拟→策略推演→生成报告。10余种保护策略按建筑类别分类，每种策略包含工期、费用、有效性、材料、步骤、优缺点，并支持50年效果模拟。

**4）历史GIS时空关联**

识别结果自动关联地理坐标与历史行政区划，生成三期历史时间轴，展示建筑在不同朝代的区域角色演变，将单体建筑置于宏观历史地理语境中理解。

**5）全离线本地存储**

基于IndexedDB（Dexie ORM）构建五张本地数据表（识别历史、收藏建筑、病害记录、对比组、系统设置），无需服务端即可实现数据持久化，保护用户隐私。

### 2.2 多模态AI识别引擎

#### 2.2.1 技术方案

本系统核心识别能力基于智谱GLM-4V-Plus多模态视觉语言大模型，通过精心设计的Prompt工程和多图融合策略，实现对中国古建筑的高精度结构化识别。

**识别流程：**

```
用户上传多张图片
    ↓
fileToBase64Many() ── 批量转换为Base64编码
    ↓
recognizeBuildingMulti() ── 构造多图请求
    ↓
┌──────────────────────────────────┐
│   GLM-4V-Plus 多模态推理          │
│   输入: N张图片 + 结构化Prompt     │
│   约束: 仅1911年前中国古建筑       │
│   输出: 严格JSON Schema           │
└──────────────────────────────────┘
    ↓
validateResult() ── 模式验证与归一化
    ↓
parseComponents() ── 构件特征推断（默认值回退）
    ↓
parseGis() ── 地理坐标+历史语境生成
    ↓
RecognitionResult ── 12项结构化输出
```

#### 2.2.2 Prompt工程设计

系统采用动态Prompt策略，根据上传图片数量自动调整提示词：

- **单图模式**：要求模型从单一视角推断建筑全貌；
- **多图模式**：要求模型进行跨视角交叉校验，输出一致性评分（Fusion Consistency Score，0-1），当一致性低于0.6时标记为低置信度结果。

Prompt中硬编码以下约束条件：
- 仅识别1911年以前的中国传统建筑（排除寺庙、佛塔等宗教建筑）；
- 输出必须为严格JSON格式，包含name、category、era、year、location、features、description、confidence等字段；
- 建筑类别限定为：民居、官府、皇宫、桥梁、其他五类。

#### 2.2.3 构件特征推断

当AI模型未输出构件详情或置信度不足时，系统根据建筑类别自动匹配默认构件特征：

| 建筑类别 | 斗拱类型 | 走兽数量 | 彩画纹样 | 屋顶形式 |
|----------|---------|---------|---------|---------|
| 皇宫 | 重昂七铺作 | 10 | 和玺彩画 | 重檐庑殿顶 |
| 官府 | 单昂五铺作 | 7 | 旋子彩画 | 歇山顶 |
| 民居 | 简化斗拱或无 | 3 | 民间彩绘 | 硬山顶 |
| 桥梁 | 无 | 0 | 无 | 无 |

置信度统一校正公式：`confidence = clamp(原始置信度 × 0.92, 0.45, 0.99)`

#### 2.2.4 识别结果数据结构

```typescript
interface RecognitionResult {
  // 基础信息（7项）
  name: string;           // 建筑名称
  category: string;       // 类别：民居/官府/皇宫/桥梁/其他
  era: string;            // 朝代
  year: string;           // 建造年份
  location: string;       // 地理位置
  features: string[];     // 建筑特征列表
  description: string;    // 详细描述
  confidence: number;     // 识别置信度 (0-1)

  // 构件细节（5项）
  components: {
    dougongType: string;     // 斗拱类型
    beastCount: number;      // 屋脊走兽数量
    beastTypes: string[];    // 走兽名称
    paintingPattern: string; // 彩画纹样
    roofType: string;        // 屋顶形式
  };

  // 多图融合（3项）
  fusion: {
    imageCount: number;       // 输入图片数
    consistency: number;      // 跨视角一致性 (0-1)
    crossViewSummary: string; // 多角度综合描述
  };

  // 历史地理（5项）
  gis: {
    placeName: string;           // 历史地名
    lat: number; lng: number;    // 经纬度坐标
    dynastyContext: string;      // 历史地理叙述
    territoryLevel: string;     // 行政级别
    timeline: Array<{           // 三期历史时间轴
      period: string;
      territoryContext: string;
      locationRole: string;
    }>;
  };
}
```

### 2.3 病害智能诊断与3D可视化

#### 2.3.1 病害数据模型

系统定义了完整的病害描述体系，涵盖6种病害类型、3级严重程度和3级紧急度：

| 维度 | 分类 | 权重 |
|------|------|------|
| 病害类型 | 裂缝(1.0)、腐蚀(0.9)、剥落(0.85)、虫蛀(0.8)、风化(0.7)、变形(1.0) | 危险系数 |
| 严重程度 | 轻微(1)、中度(2)、严重(3) | 梯度权重 |
| 紧急度 | 定期监测(1)、近期处理(2)、立即处理(3) | 响应优先级 |

#### 2.3.2 3D可视化方案

**差异化建筑模型：** 针对四种建筑类别，分别设计了参数化3D几何模型：

- **皇宫模型**：台基(7.2×5.4) + 主体木构(4.3×2.1×3.1) + 5排×2列廊柱(高2.2) + 双层重檐庑殿顶 + 金色宝顶；
- **官府模型**：基座(8.2×5.4) + 中央大堂 + 两侧厢房 + 前门楼，对称布局；
- **民居模型**：四合院式，四面围墙各带坡屋顶，中央天井，方正布局(7.2×7.2)；
- **桥梁模型**：桥面(9.5×1.4) + 4座桥墩 + 拱形跨度 + 14段石栏杆 + 水面效果。

**三种视图模式：**

| 模式 | 说明 | 用途 |
|------|------|------|
| 总览模式 | 自动旋转，完整展示 | 初次了解建筑形态 |
| 爆炸模式 | 斗拱/屋顶垂直分离 | 观察内部构件关系 |
| 线框模式 | 仅显示几何骨架 | 研究结构逻辑 |

**病害热力球映射：**

每种建筑类型预设了关键构件热点位置（三维坐标），系统将病害记录匹配到对应构件，生成热力球：

```
颜色编码：
  红色(#ef4444)：热力值 > 0.7（严重）
  橙色(#f59e0b)：0.4-0.7（中度）
  黄色(#eab308)：< 0.4（轻微）

球体半径：0.3 + 热力值 × 0.2
透明度：常态35%，选中60%
```

#### 2.3.3 病害恶化预测模型

系统内置基于时间衰减的病害恶化预测模型，可推演4个时间节点的病害发展趋势：

| 预测年份 | 恶化乘数 | 示例：当前严重度60% |
|----------|---------|-------------------|
| 5年后 | ×1.3 | 78% |
| 10年后 | ×1.8 | 100%（封顶） |
| 20年后 | ×2.8 | 100% |
| 50年后 | ×4.5 | 100% |

每个时间节点输出：
- **恶化程度**（severityProgression, 0-100）
- **扩散范围**（areaSpread, 0-100）
- **结构安全评分**（structuralSafetyScore, 0-100）
- **维修紧急度**（低/中/高/紧急）
- **费用倍数**（costMultiplier）
- **文字描述**

### 2.4 多维度病害对比分析算法

#### 2.4.1 四维相似度计算

系统支持两种对比模式：**空间对比**（两座不同建筑）和**时间对比**（同一建筑不同时期）。核心算法采用四维加权相似度模型：

```
总体相似度 = 类型相似度 × 0.35
           + 严重度相似度 × 0.30
           + 位置相似度 × 0.20
           + 紧急度相似度 × 0.15
```

**各维度计算方法：**

| 维度 | 权重 | 算法 | 说明 |
|------|------|------|------|
| 类型相似度 | 35% | Dice系数：`(共同类型×2)/(类型A+类型B)×100` | 衡量病害种类重合程度 |
| 严重度相似度 | 30% | 余弦相似度：基于(轻微/中度/严重)分布向量 | 衡量病害程度分布一致性 |
| 位置相似度 | 20% | Dice系数：基于构件位置映射（柱/梁/墙/基/顶/饰/拱/墩） | 衡量病害空间分布相似性 |
| 紧急度相似度 | 15% | 余弦相似度：基于(监测/近期/立即)分布向量 | 衡量应急响应需求一致性 |

#### 2.4.2 相似病害配对算法

对于两座建筑的病害逐条配对，采用多因素叠加评分：

```
配对相似分 = 50（同类型基础分）
           + 25（同构件位置）
           + 15（同严重程度）
           + 10（同紧急度）
满分：100
```

#### 2.4.3 时序趋势分析

在时间对比模式下，系统计算以下健康指标：

```
健康评分 = 100 - (严重×30 + 中度×15 + 轻微×5 + 立即×25 + 近期×10)
恶化速率 = 评分变化量 / 时间跨度（天）
趋势判定：恶化速率 > 0 → 持续恶化 | < 0 → 状况改善 | ≈0 → 基本稳定
```

#### 2.4.4 对比报告

系统自动生成完整的对比报告，包含：
- 执行摘要（总体相似度、关键发现）
- 详细对比（逐病害配对分析）
- 相似度分析（四维雷达图数据）
- 时间轴分析（趋势判定、恶化速率）
- 保护建议（按优先级排序，含参考案例和费用估算）

支持一键导出报告，便于存档和汇报。

### 2.7 创新实验室：AI风险模拟

#### 2.7.1 三因子压力评估模型

系统提供交互式风险模拟面板，用户可调节三项环境压力因子：

| 压力因子 | 权重 | 范围 | 类别差异化乘数 |
|----------|------|------|--------------|
| 湿度风险 | 34% | 20-100 | 民居(1.2) > 皇宫(1.15) > 官府(1.0) |
| 人流风险 | 38% | 20-100 | 桥梁(1.25) > 皇宫(1.1) > 官府(1.05) > 民居(0.9) |
| 地震风险 | 28% | 20-100 | 桥梁(1.15) > 民居(1.05) > 官府/皇宫(~1.0) |

**综合评估公式：**

```
结构压力 = round(湿度×类别乘数×0.34 + 人流×类别乘数×0.38 + 地震×类别乘数×0.28)
保护优先级 = round(结构压力×0.62 + 年代权重×0.38)
数字化价值 = round(42 + 特征数×9 + 置信度×22 - 结构压力×0.16)
```

**年代权重表：**

| 年代 | 权重 | 依据 |
|------|------|------|
| 先秦-汉 | 95 | 存世极少，历史价值最高 |
| 唐-宋 | 88 | 中古精华，学术价值极高 |
| 元 | 82 | 承上启下，独特风格 |
| 明-清 | 76 | 存量较大，工艺成熟 |
| 民国-近代 | 66 | 历史较短，但有过渡价值 |

#### 2.7.2 智能行动建议

基于评估结果，系统自动生成三级行动时间表：

1. **立即行动（7日内）**：排序前2项风险，生成应急措施（如开启分区除湿、设置分时预约）；
2. **中期优化（1季度）**：季度巡检计划、病害专项普查；
3. **长期能力（年度）**：数字孪生监测看板、可复用保护标准。

## 第四章　创新性说明

### 4.1 多模态视觉融合识别

**创新点：** 区别于传统单图识别，系统支持多角度图片联合输入，通过跨视角一致性校验（Fusion Consistency Score）提升识别可靠性。当从正面、侧面、细节等多角度上传同一建筑图片时，系统自动进行交叉验证，避免单一视角造成的误判。

**技术突破：**
- 自研的多图融合Prompt策略，在GLM-4V-Plus上实现了跨视角推理能力；
- 构件特征自动推断体系（斗拱、走兽、彩画、屋顶），即使模型输出不完整也能补全；
- 地理坐标和历史语境的自动关联，实现"识图即知史"。

### 4.2 病害时空预测模型

**创新点：** 系统不仅诊断当前病害，还通过时间衰减模型预测5-50年后的病害发展趋势，为"防患于未然"提供科学依据。

**技术突破：**
- 构件级精度的3D热力球映射，将抽象病害数据转化为空间可视化；
- 四维相似度算法（类型×严重度×位置×紧急度），实现病害的多角度量化对比；
- 时序健康评分模型，自动判定"改善/稳定/恶化"趋势。

### 4.3 保护策略沙盘推演

**创新点：** 打破传统"问题→方案"的线性决策模式，引入沙盘推演思维，让决策者在虚拟环境中预览不同策略的50年长期效果。

**技术突破：**
- 按建筑类别组织的策略知识库，包含完整的实施要素（材料、步骤、优缺点）；
- 三因子压力评估模型（湿度×人流×地震），且考虑建筑类别差异化系数；
- 年代加权的保护优先级算法，先秦建筑（权重95）优先于明清建筑（权重76）。

### 4.4 全链路数字化保护闭环

**创新点：** 首次将"AI识别→病害诊断→对比分析→风险模拟→策略推演"5个环节无缝串联，形成从发现到保护的完整数字化闭环。

```
发现阶段：上传图片 → AI识别建筑 → 结构化档案
          ↓
诊断阶段：自动匹配病害热点 → 3D空间可视化 → 预测未来恶化
          ↓
分析阶段：跨建筑横向对比 → 时间纵向趋势 → 四维量化报告
          ↓
决策阶段：环境风险模拟 → 策略沙盘推演 → 50年效果预测
          ↓
存档阶段：全数据本地持久化 → 可导出报告 → 支持长期追踪
```

这一闭环使得即便是没有专业背景的基层文保人员，也能借助系统完成从发现文物到制定保护方案的全流程工作。

## 第五章　总结

### 5.1 项目成果

"古建智识"系统成功实现了以下技术成果：

1. **构建了专为中国古建筑设计的多模态AI识别引擎**，支持多角度融合识别，单次输出12项结构化指标，覆盖皇宫、官府、民居、桥梁四大类别共20座典型建筑的知识库；

2. **开发了基于Three.js的交互式3D可视化系统**，四种差异化建筑模型、三种视图模式、病害热力球空间映射、50年恶化预测时间轴；

3. **设计了四维加权病害对比算法**，支持空间对比和时间对比两种模式，自动生成包含执行摘要、详细分析和保护建议的完整报告；

4. **建立了保护策略决策沙盘**，内置10余种按类别分类的保护策略，每种策略提供完整实施方案和50年效果模拟；

5. **实现了历史GIS时空关联**，识别结果自动匹配地理坐标和三期历史时间轴，将建筑置于宏观历史语境中理解；

6. **打造了高性能前端架构**，首屏Gzip仅~80KB，路由级懒加载，Three.js按需加载，图片自动压缩，支持Web和Electron桌面双端部署。

### 5.2 应用价值

**实际应用价值：**

- **降低门槛**：将古建筑识别从"需要数十年经验"降低到"上传照片即可"，使基层文保人员和志愿者成为有效的文物保护力量；
- **提升效率**：AI辅助识别+自动报告生成，将单次勘察周期从3-7天压缩到分钟级；
- **科学决策**：四维量化分析+50年预测模拟+策略沙盘推演，让保护决策从经验驱动转向数据驱动；
- **文化传承**：3D沉浸式展示+历史GIS+知识图谱，让古建筑知识以直观、生动的方式传播；
- **数据积累**：离线存储+结构化记录，为长期文物保护提供数据基础。

**未来规划：**

- 接入更多AI模型进行集成识别，提升准确率；
- 扩展建筑知识库至100+座，覆盖全国主要古建筑；
- 引入点云数据实现更精确的3D重建；
- 开发协同工作模式，支持多人远程勘察。
